# Yashik

Лицензия: [MIT](LICENSE).

Yashik — Rust CLI для проверки YAML-манифеста глобального окружения AI-клиентов.
Этап 1 реализует проверку схемы: `init` показывает эффективные ресурсы, не
устанавливая программы и не изменяя конфигурацию. На Linux прошла полная
проверка с upstream-исходниками YAML parser: 15 тестов (10 core, 3 YAML, 2 CLI)
и smoke test бинарника. Обычные `cargo build` и `cargo test` пока не могут
разрешить зависимости из crates.io из-за недоступного DNS; macOS не проверялась.
Подробности — в [протоколе прогона](docs/features/rust-schema/run.md) и
[Review](docs/features/rust-schema/review.md).

Целевые платформы — Linux и macOS; первые ручные проверки запланированы на
Ubuntu. Адреса и токены в примере манифеста — placeholders.

## Сценарий работы

1. Для обычной сборки и запуска тестов обеспечить доступ к Cargo registry.
2. Запустить `yashik init ./yashik.yaml`: на текущем этапе команда только
   проверит манифест и выведет включённые harnesses и имена ресурсов.
3. Самостоятельно авторизоваться в клиентах и сервисах, если это требуется.

В проверенной локальной сборке пример запускается из корня репозитория так:

```sh
./target/debug/yashik init examples/yashik.yaml
```

Эта сборка использовала временные Cargo path patches к проверенным upstream
исходникам из `/tmp`; сами зависимости и временный lockfile не добавлены в
репозиторий. Для текущей среды этот бинарник собран, а его воспроизводимая
сборка через crates.io ожидает восстановления DNS.

Целевые команды:

```text
yashik init ./yashik.yaml
yashik doctor
```

`doctor` пока сообщает, что диагностика ещё не реализована, и завершается с
ошибкой. Команда `init` на этапе 1 не читает исходники ресурсов, не скачивает
зависимости, не запускает install steps и не меняет HOME или конфиги.

## Планируемый объём

Планируемая версия охватывает Codex, Claude Code, OpenCode, Pi и Oh My Pi (OMP)
и управляет ресурсами только в глобальном пользовательском окружении. Она
будет управлять CLI клиентов, MCP-серверами, skills, agents и rules. Общие ресурсы
адаптируются для каждого включённого клиента; локальный блок может заменить
ресурс по имени или отключить его. Portable agents и rules адаптируются для
клиентов; также можно указать нативный ресурс для отдельного клиента. Если
возможность не поддерживается, Yashik объяснит это и спросит, пропустить или
отменить установку данного ресурса.

Источники указываются явно: Git-репозитории, в том числе приватные через уже
настроенную авторизацию Git, и локальные файлы или каталоги. Относительный путь
разрешается от каталога манифеста. Недостающие runtime и CLI устанавливаются
только через поддерживаемые рецепты. Шаги установки задаются массивами
аргументов, без неявного shell. Полный SHA коммита закрепляет Git-источник; без
`ref` при каждом `init` заново разрешается последняя default branch.

Модели, providers, permissions, hooks, проектная установка, unattended-режим,
экспорт окружения и поиск по marketplace не входят в первую версию. См.
[требования](docs/requirements.md), [спецификацию и roadmap](docs/design.md) и
[пример манифеста](examples/yashik.yaml).
