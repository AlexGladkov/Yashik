# Plan: манифест по умолчанию для `init`

## Ожидаемое поведение и границы

- `yashik init` читает только `./yashik-compose.yaml` из текущего рабочего каталога процесса. Манифест и относительные локальные ресурсы проходят существующие загрузку, валидацию и установку.
- `yashik init <путь>` сохраняет прежний приоритет: указанный файл используется независимо от наличия `yashik-compose.yaml`.
- `yashik check <путь>` по-прежнему требует аргумент. Поиск в родителях, другие имена и fallback не добавляются. Лишние аргументы остаются ошибкой CLI.
- Если файла по умолчанию нет, ошибка называет `yashik-compose.yaml` и подсказывает передать путь явно. До успешной загрузки и валидации состояние установщика не создаётся.

## Решения и зависимости

- В нативном CLI добавить ветку `init` без аргумента, передающую относительный путь `yashik-compose.yaml` в `load_effective`. Ошибку чтения этого файла дополнить подсказкой; остальные ошибки явного пути и YAML сохранить.
- В Windows launcher разрешить ноль или один операнд только для `init`; при нуле передавать в WSL один аргумент `init`, чтобы нативный CLI выбрал файл. Существующее преобразование явно указанного Windows-пути и прямая передача абсолютного Linux-пути остаются в силе. Согласно [документации Microsoft о файловых системах WSL](https://learn.microsoft.com/en-us/windows/wsl/filesystems), команда WSL, вызванная из Windows, наследует текущий каталог. Реальное поведение на Windows/WSL нужно подтвердить отдельно: mock не проверяет сопоставление каталогов.
- Обновить help и пользовательские шаги README на имя `yashik-compose.yaml` и короткую команду `init`; для `check` указывать путь. В `docs/design.md` обновить действующий пример использования. Исторические отчёты и существующий `examples/yashik.yaml` как иллюстрацию схемы не переименовывать.

## Реализация и приёмка

1. Изменить диспетчеризацию и сообщение об отсутствующем файле в `src/main.rs`.
2. Изменить разбор `init` и help в `tools/windows-launcher/src/lib.rs`, сохранив строгий разбор `check`.
3. Добавить CLI-проверки с явным `current_dir`: файл по умолчанию в cwd, явный путь при наличии обоих файлов, отсутствие файла и отсутствие поиска в родителях, невалидный YAML без записи состояния, отказ `check` без пути и лишних аргументов. Проверить, что относительные ресурсы привязаны к каталогу выбранного манифеста.
4. Добавить mock-проверки Windows для `init` без операнда и с явным Windows/Linux-путём, обязательного операнда `check` и отказа лишних аргументов.
5. Обновить README и действующее описание в `docs/design.md`.
