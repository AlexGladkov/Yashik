# Требования из интервью

- Rust CLI; Linux и macOS. Первые ручные испытания — Ubuntu.
- Сначала установка самого Yashik, затем `yashik init` с вручную написанным YAML.
- Харнессы: OMP, Codex, Claude Code, OpenCode, Pi.
- Установка CLI и назначенных им MCP, skills, subagents, rules.
- Compose-подобный YAML: общие блоки применяются ко всем харнессам;
  локальные блоки относятся к конкретному харнессу и переопределяют общие по имени.
- Общие rules и субагенты имеют единый формат с адаптацией под харнессы;
  также допускаются нативные версии для отдельных харнессов.
- Только пользовательское глобальное окружение, без установки в проект.
- Источники: явные инструкции установки, Git (включая приватные через уже
  настроенную авторизацию), локальные файлы и каталоги.
- Закрепление версий; без версии — последняя доступная.
- Повторный `init` вычисляет изменения и доставляет необходимое.
- `doctor` показывает установленные компоненты и их состояние.
- Существующие настройки: спросить пользователя об объединении или замене,
  сохранить резервную копию.
- Ранее управляемый ресурс удалён из YAML: спросить перед удалением.
- Неподдерживаемая возможность: объяснить и спросить, пропустить или отменить
  установку данного ресурса.
- Ошибки независимых установок не останавливают остальные; итоговый отчёт
  показывает успехи и ошибки.
- Пользователь авторизуется в харнессах и сервисах самостоятельно.
- Недостающие зависимости устанавливаются автоматически; sudo при необходимости.
- Первая версия интерактивная, без unattended-режима.
- Настройки моделей, провайдеров, permissions и hooks не входят в первую версию.
- Экспорт YAML с текущей машины — позже.
- Маркетплейс/установка по handle и повторное использование каталогов харнессов:
  будущая возможность; точный объём первой версии ещё не согласован.

Разработка проходит по `.agents/skills/business-feature/SKILL.md`.
